# TIR Parts — специфікація проєкту (для Claude Code)

> Інтернет-магазин запчастин для вантажівок (тягачі, вантажні авто, напівпричепи) з особистим кабінетом, «гаражем» авто клієнта, підбором за VIN та адмін-панеллю.
>
> **Поточна мета: ДЕМО-версія**, яку можна показати власникам бізнесу, зібрати корективи і далі допрацювати до продакшену. Все, що позначено 🟢 — робимо в демо. 🟡 — закладаємо в архітектуру, але реалізуємо пізніше. 🔴 — тільки після погодження з власниками.

## 1. Контекст і що показав аналіз ринку

**Конкуренти (UA):** спеціалізовані магазини запчастин для вантажівок (типу 7Truck-TIR, «Далекобійник», маркетплейсні продавці на Prom/OLX) і великі дистриб'ютори (Inter Cars, Exist).

Типова картина у нішевих TIR-магазинів:
- сайт = каталог + кошик, дизайн застарілий, мобільна версія слабка;
- підбір за VIN заявлений, але фактично це форма «залиште VIN — вам передзвонять»; частина магазинів прямо пише, що підбір складний і краще телефоном;
- немає «гаража» з авто клієнта, історії «що ставили на цю машину», немає B2B-функцій для автопарків;
- окремо від тягача ніхто нормально не веде напівпричепи (осі BPW / SAF / ROR), хоча для TIR це половина продажів.

**Джерела даних для підбору:**
- **TecDoc (TecAlliance)** — галузевий стандарт. Є API: VIN → kType → список сумісних артикулів, пошук за OE-номером, нечіткий пошук за будь-яким номером, «де застосовується деталь». Існує окремий **TecDoc VIN Catalogue – Truck** для 7 основних брендів вантажівок. Платна ліцензія → 🟡.
- **Оригінальні EPC-каталоги** (MAN, Scania, Volvo, DAF, Mercedes, Iveco, Renault Trucks) — доступні через онлайн-сервіси, ними користуються менеджери вручну.
- Важливо: у вантажівок деталь часто залежить від **номера шасі в межах однієї моделі** (до номера X — одна деталь, після — інша). Тому VIN/номер шасі критичний, а «марка + модель + рік» не достатні.

**Юридичні/операційні вимоги UA (для продакшену, не для демо):**
- ПРРО обов'язковий для онлайн-продажу; при відправці Новою Поштою чек формується до відправки. Інтеграція через API ПРРО (Checkbox тощо) 🟡.
- Нова Пошта API 2.0 — пошук міст/відділень, розрахунок вартості, створення ТТН 🟡.
- Оплата: LiqPay / Monobank еквайринг, рахунок для юросіб (з ПДВ/без), накладений платіж 🟡.

## 2. Унікальна цінність (що відрізнятиме від конкурентів)

1. **Гараж / Автопарк** — клієнт додає тягачі **і причепи** один раз (VIN, двигун, коробка, осі, Euro-клас, держномер, пробіг). Далі весь каталог фільтрується «під цю машину» одним кліком.
2. **Гібридний VIN-підбір** — автоматика там, де дані є, + запит менеджеру там, де немає. Менеджер відповідає прямо в кабінеті списком деталей → клієнт одним кліком кладе в кошик.
3. **Власна база «VIN → OE-номери»** — кожна відповідь менеджера зберігається за авто. З часом магазин має власну базу підбору, якої немає у конкурентів (це головний актив проєкту).
4. **Історія по авто** — що і коли купували на кожну машину; пробіг при покупці.
5. **Комплекти ТО** — «ТО для DAF XF 106 MX-13» = фільтри + масло + ремені, одним кліком.
6. **B2B для автопарків** 🟡 — компанія з кількома користувачами (власник, механік, бухгалтер), персональні ціни, рахунки, ліміт відстрочки.
7. **Пошук за номером деталі як головний вхід** — один рядок пошуку розуміє OE-номер, артикул виробника, крос-номер, VIN, назву деталі. Номери нормалізуються (без пробілів/дефісів/крапок).

## 3. Обсяг ДЕМО

### 🟢 Робимо зараз
- Головна, каталог, картка товару, пошук (з нормалізацією номерів), кошик, оформлення замовлення (без реальної оплати — статус «очікує підтвердження»).
- Реєстрація/вхід (email + пароль; телефон OTP — заглушка).
- Особистий кабінет: профіль, **Гараж** (CRUD авто й причепів), замовлення, **VIN-запити**.
- VIN-декодер рівня 0 (локальний, без API): визначає марку за WMI, рік за 10-м символом, перевірка контрольної суми/формату; решту полів клієнт уточнює вручну.
- Підбір «під моє авто»: фільтрація товарів за правилами застосовності (марка, серія, двигун, роки, діапазон шасі) + за OE-номерами, прив'язаними до авто.
- VIN-запит менеджеру → менеджер в адмінці додає позиції → клієнт бачить відповідь і додає в кошик.
- Адмін-панель: дашборд, товари (CRUD + фото), категорії, бренди, застосовність, крос-номери, замовлення (статуси), VIN-запити, клієнти, комплекти ТО, банери, базові налаштування магазину, **імпорт товарів з XLSX/CSV**.
- Реалістичні демо-дані (seed) для DAF, MAN, Volvo, Scania, Mercedes, Renault, Iveco + причепи BPW/SAF.
- Адаптивність (телефон водія — пріоритет), світла + темна тема.

### 🟡 Закладаємо в архітектуру, робимо після погодження
- Нова Пошта, онлайн-оплата, ПРРО, рахунки для юросіб.
- TecDoc API (через інтерфейс `VinProvider` / `CatalogProvider`).
- B2B-компанії, рівні цін, відстрочка.
- Telegram-бот сповіщень, SMS OTP.
- Інтеграція з обліковою системою (1С/BAS/інше — уточнити) для залишків і цін.
- Багатомовність (UA основна, EN/PL — для далекобійників за кордоном).

### 🔴 Тільки за рішенням власників
- Склади в кількох містах, маркетплейс-фіди (Prom/Rozetka), бонусна програма, мобільний застосунок.

## 7. Ключові сценарії

### 7.1 Додавання авто в гараж
1. Клієнт вводить VIN (17 символів) або номер шасі.
2. `VinService.decode()` → марка (WMI), рік (10-й символ), тип (тягач/причіп за WMI), валідність.
3. Форма з автозаповненими полями + ручне уточнення: серія/модель (з довідника), двигун, Euro-клас, КПП, колісна формула, тип кабіни, осі (для причепа), держномер, назва («Білий DAF Петра»), пробіг.
4. Збереження → картка авто → пропозиція «Надіслати менеджеру для точного підбору» (необов'язково).

### 7.2 Підбір товарів під авто (алгоритм)
Товар **точно підходить**, якщо виконується одне з:
- у авто є прив'язаний OE-номер, і товар має цей OE-номер або крос на нього;
- товар має правило застосовності, яке збігається з авто: `brand` = ✔, `series` = ✔ (або null), `engineCode` = ✔ (або null), `yearFrom ≤ рік ≤ yearTo`, `chassisFrom ≤ шасі ≤ chassisTo` (якщо задано).

**Можливо підходить** — збіг тільки за маркою/серією без уточнень → показуємо з позначкою «Уточніть у менеджера».

Результат показуємо з бейджами: ✔ Підходить · ? Уточнити · ✖ Не підходить.

### 7.3 VIN-запит менеджеру
1. Клієнт з картки авто або зі сторінки `/vin`: обирає авто (або вводить VIN як гість + телефон), описує що потрібно («колодки передні, фільтр паливний»), може додати фото.
2. Запит з'являється в адмінці зі статусом `NEW` і таймером SLA.
3. Менеджер шукає товари, додає їх у відповідь (кількість, коментар), за потреби прив'язує знайдені OE-номери до авто клієнта.
4. Статус `ANSWERED` → клієнт отримує email (🟡 Telegram/SMS) → бачить список → «Додати все в кошик» або вибірково.
5. OE-номери, прив'язані до авто, далі автоматично працюють у підборі (7.2).

### 7.4 Оформлення замовлення (демо)
Кошик → контакти → доставка (самовивіз / Нова Пошта — в демо просто текстові поля міста і відділення) → оплата (готівка / рахунок / карта — в демо без реального платежу) → прив'язка до авто з гаража (необов'язково, для історії) → замовлення `NEW` → менеджер в адмінці підтверджує.

## 8. Модель даних

Повна актуальна схема — `prisma/schema.prisma` (розширена версія моделі з первинної специфікації).

Індекси: `Product.articleNorm`, `ProductNumber.numberNorm`, `VehicleOeNumber.oeNumber`, `Fitment(makeId, seriesId, engineCodeId)`, trigram-індекс на `Product.name`.

## 9. VIN — архітектура

```ts
// src/server/vin/types.ts
export interface DecodedVin {
  vin: string;
  valid: boolean;
  wmi: string;
  make?: string;            // з таблиці WMI
  kind?: VehicleKind;
  modelYear?: number;       // 10-й символ (з урахуванням циклу 30 років — повертати кандидатів)
  serial?: string;          // символи 12–17 — використовувати як chassisNumber для діапазонів
  confidence: "low" | "medium" | "high";
  source: string;           // "local" | "tecdoc" | ...
  raw?: unknown;
}
export interface VinProvider {
  name: string;
  decode(vin: string): Promise<DecodedVin | null>;
  findParts?(vin: string, opts?: { category?: string }): Promise<{ oeNumbers: string[] } | null>;
}
```

- `LocalVinProvider` 🟢 — WMI-таблиця з БД (`VehicleMake.wmiCodes`), рік, валідація (17 символів, без I/O/Q).
- `TecDocVinProvider` 🟡 — VIN → kType → сумісні артикули / OE.
- `VinService` викликає провайдерів по черзі (local → tecdoc), кешує результат у `Vehicle.decodedJson`.

Стартова WMI-таблиця для seed (**перевірити перед продакшеном**): DAF `XLR`, MAN `WMA`, Scania `YS2`, Volvo Trucks `YV2`, Mercedes-Benz `WDB`/`W1T`, Renault Trucks `VF6`, Iveco `ZCF`, Schmitz Cargobull `WSM`, Krone `WKE`.

Нормалізація номерів: `normalize = s => s.toUpperCase().replace(/[^A-Z0-9]/g, "")`. Застосовувати при збереженні і при пошуку. Якщо запит після нормалізації схожий на VIN (17 символів) — пропонувати «Розшифрувати VIN».

## 10. Пошук
Порядок видачі:
1. точний збіг `articleNorm`;
2. точний збіг `ProductNumber.numberNorm` (OE/крос) → позначка «Аналог для OE …»;
3. префіксний збіг номерів;
4. текстовий пошук за назвою (`pg_trgm`), з урахуванням синонімів (подушка ↔ пневморесора ↔ пневмобалон; колодки ↔ накладки) — таблиця синонімів в налаштуваннях 🟡.

Автокомпліт у шапці: товари + категорії + «Розшифрувати VIN».

## 11. Дизайн

**Настрій:** «індустріальний хайтек» — як приладова панель сучасного тягача: чисто, контрастно, впевнено. Не «іграшковий» і не перевантажений.

- **Палітра:** графітовий/майже чорний фон у темній темі, світла тема — холодний сірий. Акцент — **сигнальний бурштиновий** (як габаритні вогні, `#FFB020`-ish) для CTA; статуси: зелений (є/підходить), бурштин (уточнити), червоний (не підходить/немає).
- **Шрифти:** Manrope або Inter для тексту; **JetBrains Mono** для артикулів, OE-номерів, VIN (номери мають читатися ідеально, з кнопкою «копіювати»).
- **Елементи:** великий пошук на головній як центральний об'єкт; картки авто в гаражі у вигляді «технічного паспорта» (силует тягача/причепа, ключові параметри моноширинним шрифтом); тонкі лінії-сітка, легкі мікроанімації наведення.
- **Зручність:** мінімум кроків; великі зони натискання (водій з телефону, можливо в рукавицях); липка панель «Моє авто: DAF XF 106 ▾» у шапці — перемикає контекст підбору на всьому сайті; кошик доступний з будь-якого екрана.
- **Адмінка:** щільні таблиці, швидкі фільтри, гарячі клавіші для пошуку (`/`), інлайн-редагування ціни/наявності.
- **Доступність:** контраст AA, фокус-стани, коректні label.
- **Без** згенерованих логотипів реальних марок — у демо марки показуємо текстом або нейтральними іконками; реальні логотипи — лише за наявності прав.

## 13. Структура проєкту
```
src/
  app/
    (shop)/            публічні сторінки + layout з шапкою/футером
    account/           кабінет (guard: CUSTOMER+)
    admin/             адмінка (guard: MANAGER+), окремий layout з сайдбаром
    api/               route handlers (імпорт, завантаження файлів)
  components/
    ui/                shadcn
    shop/  account/  admin/  shared/
  server/
    db.ts              prisma client
    auth/              конфіг, guards (requireRole)
    services/          catalog.ts, search.ts, fitment.ts, cart.ts, orders.ts, vinRequests.ts, import.ts, settings.ts
    vin/               types.ts, local-provider.ts, service.ts
    providers/         (🟡 novaposhta, payments, prro, tecdoc)
  lib/                 normalize.ts, format.ts (гривні, дати), validators (zod)
prisma/
  schema.prisma, seed.ts, seed-data/
```

Правила: бізнес-логіка тільки в `src/server/services`; компоненти не ходять у Prisma напряму; кожна мутація в адмінці пише `AuditLog`; всі ціни — `Decimal`, відображення через `Intl.NumberFormat('uk-UA', { style: 'currency', currency: 'UAH' })`.

## 14. Етапи

1. **Каркас.** Next.js + TS + Tailwind + shadcn/ui, теми (світла/темна), шрифти, токени кольорів з розділу 11, базові layout'и (shop/account/admin), Prisma + PostgreSQL, docker-compose для БД, `.env.example`, `CLAUDE.md` з правилами з розділу 13.
2. **Схема і seed.** Повна Prisma-схема, міграції, seed з розділу 12, утиліта `normalize`.
3. **Авторизація і ролі.** Реєстрація, вхід, вихід, `requireRole`, захист `/account` і `/admin`, демо-підказка входу.
4. **Каталог і пошук.** Категорії, список з фільтрами й пагінацією, картка товару (номери, застосовність, аналоги), пошук за алгоритмом розділу 10, автокомпліт.
5. **VIN і Гараж.** `LocalVinProvider` + `VinService`, сторінка `/vin`, гараж (CRUD авто й причепів), перемикач «Моє авто» в шапці, сервіс `fitment.ts` (розділ 7.2), бейджі ✔/?/✖ у каталозі й картці.
6. **Кошик і замовлення.** Кошик (гість + користувач, злиття при вході), checkout за 7.4, сторінки замовлень у кабінеті, історія покупок по авто.
7. **VIN-запити.** Створення клієнтом/гостем, тред повідомлень, відповідь менеджера з товарами, «Додати все в кошик», прив'язка OE-номерів до авто.
8. **Адмінка — ядро.** Дашборд, замовлення, VIN-запити, клієнти.
9. **Адмінка — каталог.** Товари (вкладки з розділу 6), категорії (drag&drop), бренди/марки/серії/двигуни, застосовність, комплекти ТО, завантаження фото.
10. **Імпорт.** XLSX/CSV → мапінг колонок (зберігати шаблони мапінгу) → передперегляд 20 рядків → імпорт (створити/оновити за `article`+`brand`) → звіт з помилками.
11. **Контент і налаштування.** Банери, сторінки, налаштування магазину, користувачі й ролі, журнал дій.
12. **Головна і полірування.** Головна сторінка, порожні стани, скелетони, 404/500, SEO-мета, sitemap, мобільна перевірка всіх сторінок, Lighthouse.

Після етапу 12 — **показ власникам** і збір корективів (розділ 15).
